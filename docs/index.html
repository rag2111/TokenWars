Overview & agenda

Token Wars: Build, Route & Optimize Your AI Stack

Your AI is already in production. Now the token bill is growing faster than your users.

Token Wars is a competitive, hands-on microhack for teams that already have GenAI in production and want it faster, cheaper and more under their control, without losing quality. Teams start from a working GenAI app with a costly baseline and compete to deliver the best quality for the lowest cost per successful task. A live leaderboard tracks every change.

How it all fits together

Every workload question goes through the same answer pipeline, and each TODO lights up one block. Make each block cheaper without letting the judge's pass rate drop below 85%.

The scenario

The scenario: ByteCart Support Copilot

ByteCart is a fictional, fast-growing digital-native e-commerce marketplace based in the EU (prices in EUR). Its GenAI Support Copilot answers customer questions about returns, shipping, payments, ByteCart Plus membership, marketplace sellers, warranties, coupons, gift cards, privacy and orders.

It works, but it's expensive. Your team inherits the app and has to cut the cost per successful answer while keeping quality above the bar.

Why the baseline is so expensive

🧠 Always frontier

Every question, even "can I return shoes?", goes to gpt-5.6-sol.

Fixed in Ch. 2 & 3

📚 Whole KB in every prompt

~10 policy docs (~7–9k tokens) get pasted in even when a single section would answer the question.

Fixed by TODO 1.2

📦 Whole orders DB in every prompt

All ~60 orders go in as JSON, even for questions that have nothing to do with an order.

Fixed by TODO 1.3

⏰ Dynamic data at the top

Current date and time: {{now}} (down to the second) and the customer ID open the system prompt, so no two prompts share a prefix and prompt caching never kicks in.

A verbose prompt asks for headings, empathy paragraphs and "always recap the full policy", and output tokens cost 6× input on gpt-5.6-sol.

♻️ No caching

The workload

shared/data/workload.jsonl holds 100 questions, processed in file order:

FAQ ~40Orders ~25Policy ~20Compl. ~15
  • FAQ (easy). ~25 repeat or paraphrase earlier ones, which rewards caching.
  • Order status (easy/medium). ~70% name an order ID (BC-12345 format); the rest say "my last order".
  • Policy reasoning (hard). Needs 2+ interacting rules, e.g. Plus members get 60-day returns except electronics, which stay at 30 days.
  • Complaints (medium).
  • ⚠ A few trap pairs: very similar wording but a different order ID or customer. They punish naive semantic caching.

"Today" in the scenario is fixed at 2026-09-15.

Rules & scoring

Rules & scoring

The one number that matters

cost per success = total_cost_usd ÷ max(successes, 1)

Lower is better, but it only counts if your run is VALID:

pass_rate = successes ÷ items ≥ 0.85

From shared/config/scoring.json: {"pass_score": 4, "min_pass_rate": 0.85, "judge_model": "judge", "judge_concurrency": 8}

How an answer is judged

  • An LLM judge (the judge deployment, running gpt-5.6-terra) scores each answer 1–5 against a reference answer and the must_include facts.
  • success = score ≥ 4. A 4 means correct, minor omissions, all must-include facts present.
  • Verbosity is neither rewarded nor penalised. Short is fine.
  • "I'll escalate to a human" without actually answering scores 2 at most.
  • Items that error out score 0. With --no-judge, items are marked "not judged" and count as not successful.

💰 What is costed

Every model call your app makes: answers, classifier calls, embeddings and escalations. Per call: (uncached input × input price + cached input × cached price + output × output price) ÷ 1M, using the model's pricing_key, even when the call goes through the gateway.

⚖️ What isn't costed

Judge calls. They're tracked separately as judge_cost_usd and are not part of your score.

🚫 Fair play

Only id, customer_id and question go into the pipeline. Leave the shared workload, judge prompt, pricing and scoring config alone. The leaderboard refuses mock runs.

  1. cost_per_success_usd: your leaderboard metric, total_cost_usd ÷ max(successes,1). Lower wins.
  2. pass_rate: share of items with judge score ≥ 4. Check it after every change.
  3. valid: true when pass_rate ≥ 0.85. Otherwise you get "INVALID ❌ (pass rate below 85%)", and the run can't win however cheap it is.
  4. total_cost_usd: the sum of all costed calls (answers, classifier, embeddings, escalations).
  5. input_tokens / cached_input_tokens / output_tokens: Challenge 1 shrinks input and output. Cached input only grows once your prompt prefix is stable (TODO 1.7), and it's always 0 in mock mode.
  6. cache_hits_exact / cache_hits_semantic: answers served from your response cache at zero model cost (TODO 1.5 / 1.6).
  7. escalations: how often a cheaper model answered ESCALATE and the item moved up a tier (TODO 3.3). A few is healthy; a lot means your routing is too aggressive.
  8. latency_p50_ms / latency_p95_ms: user experience. Caching lowers them; escalations and retries push p95 up.
  9. judge_cost_usd: shown for transparency. It isn't part of your score.
  10. calls_by_model: calls, tokens and cost per model key. This is where you see whether routing really moved traffic to nano and mini.

  • Your team's own Azure subscription (pay-as-you-go is enough; nothing in the kit needs PTU) where you can create a resource group, a Microsoft Foundry resource + project with model deployments and, optionally, API Management and Container Apps.

Troubleshooting FAQ

Terraform complains that the subscription ID is missing.

The azurerm provider requires one. Either set subscription_id = "…" in infra/terraform.tfvars, or run export ARM_SUBSCRIPTION_ID=$(az account show --query id -o tsv) (PowerShell: $env:ARM_SUBSCRIPTION_ID = (az account show --query id -o tsv)), then apply again.

A model deployment fails with InsufficientQuota or "model not available in region".

Check what your region offers with az cognitiveservices model list --location <region> -o table. Then lower the capacity for that model in terraform.tfvars (e.g. frontier_model = { capacity = 800 }), or choose another location. If you can't use the open model, set deploy_open_model = false. Deployments are created one after another, so re-running terraform apply picks up where it stopped.

terraform init fails: the lock file doesn't match the azurerm version constraint.

The kit now pins hashicorp/azurerm ~> 5.8. Run terraform init -upgrade in infra/. azurerm 5.x registers only the resource providers listed in providers.tf, which needs Owner or Contributor on your subscription. If you really must stay on 4.x, follow the fallback comment in providers.tf (version = "~> 4.81", then remove resource_providers_to_register and logs_destination).

The apps or doctor get HTTP 401 from *.services.ai.azure.com.

Fall back to the classic host: set ai_endpoint_style = "openai" in infra/terraform.tfvars and run terraform apply. Only models.json changes (base_url becomes https://<name>.openai.azure.com/openai/v1/, also for fw_*); then run doctor again. Both hosts serve the same OpenAI-compatible v1 API.

Fireworks: "feature not registered" / the subscription isn't enabled for Fireworks.

A Subscription Owner or Contributor must register Fireworks.EnableDeploy: run infra/scripts/check-fireworks-prereqs.sh --register (PowerShell: check-fireworks-prereqs.ps1 -Register). Registration can take up to 30 minutes; re-run the script until it reports 0 blockers ("Registering" still counts as one). That's why it belongs in the pre-event checklist.

Fireworks models are missing from the catalog, or the deployment fails with "model not found".

Wrong region. Pay-per-token (Data Zone Standard) Fireworks models exist only in the US Data Zone: eastus, eastus2, centralus, northcentralus, westus, westus3. Set fireworks_location accordingly; the prereq script lists the FW-* models it can see there. Per-token models can also retire with 15 days' notice, so ask your coach for the current alternatives.

Fireworks deployment fails with InsufficientQuota.

Fireworks pay-per-token models share a default of 10M TPM per region per pool. Lower capacity in fireworks_models, try another US region, or request more quota at aka.ms/fireworks-quota.

Fireworks deployment fails with Forbidden / AuthorizationFailed.

Deploying needs the deployer role on the Fireworks Foundry project (Foundry Owner, formerly Azure AI Owner). Set fireworks_grant_deployer_role = true (and fireworks_deployer_role = "Azure AI Owner" if your tenant still uses the old name), then apply again. Role assignments can take a few minutes to propagate.

Lots of HTTP 429 from fw_fast / fw_pro.

Fireworks applies adaptive rate limits, so 429s can appear below your TPM. Turn on retry_on_throttle (TODO 3.4) and lower concurrency.

Terraform rejects my team_name.

It must be 2–20 characters of lowercase letters, digits and hyphens, starting with a letter or digit (e.g. neon-ninjas).

terraform apply takes a long time.

API Management is usually the slowest resource (v2 tiers take about 5–15 minutes). Explore the code in mock mode (--mock) while you wait.

doctor can't find the repo root, or says keys are missing.

Run commands from inside the repo (python/starterdotnet/starter/TokenWars). The app walks up to the folder containing shared/config; otherwise, set TOKENWARS_ROOT. Missing keys mean .env wasn't generated, so check that terraform apply completed.

I get TODO 1.2 not implemented yet – see …

You turned on a flag before implementing its TODO. Implement it, or set the flag back to its starter value.

ModuleNotFoundError: No module named 'requests'strategy.json not found, or the wrong strategy is used

Activate your virtual environment, run pip install -r requirements.txt in python/starter/, and run python -m tokenwars … from that folder.Run dotnet run -- … from dotnet/starter/TokenWars/. strategy.json is read from the current directory first (fallback: the project folder), or pass --strategy PATH explicitly.

Answers are empty, or output tokens are high even though answers are short.

That's reasoning. With the GPT-5.6 family, reasoning tokens are billed as output and count toward max_completion_tokens. If the cap is too low, the model can spend it all on reasoning and return an empty answer (finish_reason: "length"; the app prints an EMPTY-answer warning), which the judge fails. Raise max_output_tokens in strategy.json, or keep reasoning_effort at none/low in the model's extra_body in models.json (especially for nano, mini and the classifier). See TODO 1.4.

A model rejects temperature or max_tokens.

Reasoning models (GPT-5.6 family) need max_tokens_param: "max_completion_tokens" and supports_temperature: false in models.json; terraform writes these for you. If you changed a model through the *_model variables, set max_tokens_param and pricing_key to match, and add its price to shared/config/pricing.json.

My run says INVALID ❌.

The pass rate is below 85%. Open the latest results/run-*.json, filter for "success": false and read the judge_reasons. Usual suspects: top_k too low, a cap that truncates answers, routing to nano too aggressively, or bad semantic cache hits.

cached_input_tokens stays at 0.

Check that you're not in mock mode (it's always 0 there), that no dynamic data is left in the system message (TODO 1.7), and that the prompt is long enough for prompt caching (≥ 1,024 tokens).

The semantic cache returns wrong answers.

Order-specific questions must never be written to or read from the semantic cache. If paraphrase hits are wrong, raise semantic_cache_threshold (e.g. to 0.95).

Lots of HTTP 429 errors.

Turn on retry_on_throttle (TODO 3.4), lower concurrency, or ask your coach about capacity. Through the gateway, 429s come from your per-consumer token limit, which is by design.

The self-hosted model times out.

It runs on CPU. The first request loads the model, and every request has a 60 s timeout. Warm it up with ask, keep concurrency low, and use it mainly for SIMPLE requests.

The leaderboard rejects my submission.

Check TOKENWARS_LEADERBOARD_URL and the submit key (TOKENWARS_LEADERBOARD_KEY). Both come from leaderboard_url / leaderboard_key in terraform.tfvars, or can be edited in .env. Also make sure it isn't a mock run (TOKENWARS_MOCK=0, no --mock).

The judge is expensive. Does it hurt our score?

No. Judge calls are tracked separately as judge_cost_usd and don't count toward your score.

Can we route on the category field? It's right there in the workload.

No. Only id, customer_id and question may enter the pipeline. Using ground-truth fields means disqualification.
